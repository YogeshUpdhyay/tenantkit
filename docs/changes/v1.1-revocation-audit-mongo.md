# Change spec — v1.1: session revocation, audit log, MongoDB (Beanie) storage

Status: **Ready for implementation** · Target package version: **0.2.0** · Roadmap phase: v1.x (see [00-parent-design.md §11](../00-parent-design.md))

This is the handoff document for the implementing agent. It is self-contained: read it top to bottom, then work the packages in [§9](#9-work-packages) in order. The existing design docs (`docs/00`–`08`) remain the source of truth for everything this spec does not change; part of the work is updating them (WP7) so they stay true after this change lands.

---

## 1. Summary

Three features, one release:

1. **Session revocation.** Refresh tokens become stateful: each login creates a *session* record, every refresh rotates the token, reused refresh tokens kill the whole session, and sessions can be revoked by logout, by an admin, or automatically on deactivation and password change. `verify()` stays synchronous and storage-free; a new opt-in `await kit.tokens.verify_active()` additionally checks the session.
2. **Audit log.** tenantkit persists an append-only audit trail of every security-relevant action in its own storage (`mt_audit_events`), written in the same transaction as the action. Hosts may register optional **audit hooks** that observe each event after commit (SIEM forwarding, alerts). A permission-gated read and purge API is exposed.
3. **MongoDB storage.** A new optional adapter, `tenantkit.storage.beanie`, built on **Beanie 2.x** (PyMongo async), installed with `pip install tenantkit[mongo]`. It passes the same contract suite as the SQLAlchemy and in-memory adapters.

## 2. Decisions (agreed during design review)

| # | Decision |
| --- | --- |
| D1 | Mongo support uses **Beanie `>=2.0,<3`** (PyMongo async client, not Motor, not MongoEngine). Extra name: `mongo`. |
| D2 | Revocation covers **refresh tokens / sessions**. `verify()` remains sync and storage-free. A revoked session stops working at the latest when its current access token expires (≤ 15 min default; ≤ 10 min impersonation). Hosts wanting instant cut-off call the new async `verify_active()`. |
| D3 | Revocation operations in scope: logout (current session), logout-all (own sessions), admin revokes another subject's sessions, auto-revoke on user/admin/tenant deactivation, auto-revoke on password change (pulled forward from v2), early end of an impersonation session. |
| D4 | Revocation model is a **session record per refresh-token family** (`mt_sessions`), not a jti denylist. |
| D5 | **Refresh rotation with reuse detection**: presenting a non-current refresh token of a live session revokes that session (and its child impersonation sessions), emits `token.reuse_detected`, and raises. |
| D6 | Audit events are **stored by tenantkit** (`mt_audit_events`) — the built-in store is the source of truth. |
| D7 | Optional **audit hooks** (`audit_hooks=[...]`) observe events **after commit**; hook errors are logged and swallowed and never affect the operation. |
| D8 | Audit writes are **fail-closed**: state-changing events are written inside the same `storage.transaction()` as the change; if the audit write fails, the change rolls back. Failure events (bad login, lockout, token reuse) are written in their own transaction before the error is raised. |
| D9 | Audit read/retention API: `kit.audit.list(...)` (`audit:read`), `kit.audit.purge(...)` (`audit:purge`), `kit.sessions.purge_expired()`. No automatic TTL. Audit table is append-only except `purge`. |
| D10 | Failed-login events never contain the attempted email unless `audit.include_failed_login_email: true` (default `false`). |
| D11 | Beanie initialisation is **owned by the host**: tenantkit exposes `document_models(prefix)`; the host passes them into its single `init_beanie` call. One prefix per process. |
| D12 | The Beanie adapter **requires transactions** (replica set or mongos) by default; `health_check()` fails fast otherwise. `transactions=False` is an explicit, documented-as-unsafe escape hatch — with it, multi-step operations are not atomic **and D8's fail-closed audit guarantee does not hold**. |
| D13 | Beanie documents are adapter-internal and mapped to/from the existing domain dataclasses. UUID `_id`s with `uuidRepresentation="standard"`. |
| D14 | Breaking changes are accepted for 0.2.0: 0.1 refresh tokens are rejected (one forced re-login); `Storage` gains two required repositories; `issue_pair` signature changes. |
| D15 | Spec layout: this change spec + new sub-docs `10`, `11`, `12` + amendments to `00`, `02`, `07`, `08`, README, FastAPI example. |

## 2a. Additional decisions (signed off 2026-11-24)

These were settled after the main design review and are binding like D1–D15.

| # | Assumption | Where |
| --- | --- | --- |
| A1 | **Sliding sessions**: each refresh extends the session by the type's `refresh_ttl`; there is no absolute maximum session length. | §5.5 |
| A2 | **No concurrency grace window** for refresh: two refreshes racing with the same token trip reuse detection and end the session (affects SPAs refreshing from several tabs — clients must serialise refreshes). | §5.5 step 7 |
| A3 | `change_password` revokes **all** the subject's sessions, including the current one; the client re-logs in. | §5.5 |
| A4 | Permission-denied attempts on control-plane methods are **not** audited; `impersonation.denied` is the only denied-attempt event. | §6.2 |
| A5 | `audit.list` visibility follows the admin's **impersonation scope** (`*` or scope `all` → all; `list` → those tenants; `none` → denied). | §6.4 |
| A6 | The impersonation cap comes from the parent session's `expires_at`; the `admin_refresh_exp` claim is dropped. | §5.3 |

## 3. Out of scope

- Revocation checks inside the synchronous `verify()` (D2).
- Key rotation, async-only `verify`, tenant lifecycle hooks, sync adapters (still v2).
- MongoEngine or Motor-based adapters.
- Automatic audit/session expiry via TTL indexes or background tasks — hosts schedule `purge` calls.
- Audit export formats, audit UI, tamper-evident (hash-chained) audit logs.
- Tenant-admin self-service (still v2).

## 4. Breaking changes (copy into release notes)

1. **All refresh tokens issued by 0.1.x are rejected** after upgrading (they carry no `sid`). Every user and admin must log in once. Access tokens without `sid` are rejected too (they expire within minutes anyway).
2. **`Storage` protocol** gains required attributes `sessions: SessionRepository` and `audit_events: AuditEventRepository`, and a required method `in_transaction() -> bool`. Custom adapters must implement them and pass the extended `StorageContract`.
3. **SQLAlchemy hosts** must generate and run an Alembic migration for the two new tables (`{prefix}sessions`, `{prefix}audit_events`).
4. **`TokenService.issue_pair`** requires a new `session_id` keyword and returns the refresh `jti` on the `TokenPair` (see §5.4). Hosts calling it directly must create the session themselves or switch to the auth services.
5. **`change_password`** (admin and tenant) now revokes **all** of the subject's sessions, including the one in use; the client must log in again.
6. **Claims models** gain a required `sid` field.

## 5. Feature A — Sessions and revocation

New sub-doc to write: `docs/10-sessions-revocation.md` (content = this section, in the standard sub-doc template).

### 5.1 Domain model

Add to `domain/models.py`:

```python
SessionKind = Literal["admin", "tenant", "impersonation"]   # equals the token `typ`

@dataclass(kw_only=True)
class Session:
    kind: SessionKind
    subject_id: UUID                 # admin id (admin, impersonation) or tenant user id
    tenant_id: UUID | None = None    # tenant user's tenant, or impersonation target
    parent_id: UUID | None = None    # impersonation only: the admin session that started it
    current_jti: UUID                # jti of the only refresh token currently accepted
    expires_at: datetime             # refresh expiry of the current refresh token
    id: UUID = field(default_factory=uuid4)
    created_at: datetime = field(default_factory=now)
    last_used_at: datetime = field(default_factory=now)
    revoked_at: datetime | None = None
    revoked_reason: str | None = None     # see RevokeReason below

    @property
    def is_active(self) -> bool: ...      # not revoked and expires_at > now
```

`RevokeReason` (string constants, stored as text): `logout`, `logout_all`, `admin_revoked`, `subject_deactivated`, `tenant_deactivated`, `password_changed`, `reuse_detected`, `parent_revoked`, `impersonation_ended`.

### 5.2 Repository

Add to `storage/interfaces.py`; all methods async and must join an open `storage.transaction()`:

```python
class SessionRepository(Protocol):
    async def create(self, session: Session, /) -> Session: ...
    async def get(self, session_id: UUID, /) -> Session | None: ...
    async def rotate(
        self, session_id: UUID, *, expected_jti: UUID, new_jti: UUID,
        expires_at: datetime, used_at: datetime,
    ) -> Session | None: ...
    async def revoke(
        self, *, reason: str, at: datetime,
        session_id: UUID | None = None,
        kind: SessionKind | None = None, subject_id: UUID | None = None,
        tenant_id: UUID | None = None,
        cascade_children: bool = False,
    ) -> int: ...
    async def list(
        self, *, kind: SessionKind, subject_id: UUID, active_only: bool = True,
        limit: int = 50, offset: int = 0,
    ) -> list[Session]: ...
    async def purge_expired(self, *, before: datetime) -> int: ...
```

Contracts:

- **`rotate`** is an atomic compare-and-set: it updates `current_jti`, `expires_at`, `last_used_at` **only if** the row exists, `revoked_at IS NULL`, and `current_jti == expected_jti`. Returns the updated session, or `None` if any condition failed. Two concurrent rotations with the same `expected_jti` must result in exactly one success (contract test required). SQL: single `UPDATE … WHERE … RETURNING` (or update + rowcount check). Mongo: `find_one_and_update` with the conditions in the filter.
- **`revoke`** sets `revoked_at`/`revoked_reason` on every **not-yet-revoked** row matching **all** given filters (`session_id`, `kind`, `subject_id`, `tenant_id`) and returns the count. At least one filter is required (else `ValueError`). Already-revoked rows keep their original reason. With `cascade_children=True` it **also** revokes every not-yet-revoked row whose `parent_id` is the id of any row matched by the filters (whether or not that row was already revoked), with reason `parent_revoked`; the returned count includes them. Matched and cascaded updates happen in the same call (and transaction).
- **`list`** returns newest first.
- **`purge_expired`** hard-deletes rows whose `expires_at < before` **or** whose `revoked_at < before`. This is the only hard delete of sessions.

### 5.3 Token claim changes

- Every token (access and refresh, all three types) carries a new claim **`sid`** (session id, UUID string).
- Refresh token `jti` **is** `Session.current_jti`.
- `BaseClaims` and `RefreshClaims` gain `sid: UUID` (required). `verify()` rejects tokens without it (`InvalidTokenError`).
- The stateless impersonation refresh extras (`impersonation_role`, `admin_refresh_exp`, `reason`) may stay in the refresh token, but the **cap** now comes from the parent session's `expires_at` (see 5.5), not from a claim. Drop `admin_refresh_exp` from new tokens.

### 5.4 TokenService changes

`TokenService` stays storage-free except for the new `verify_active`.

```python
def issue_pair(self, *, typ, subject, session_id: UUID, tenant=None, roles=None,
               refresh_cap: datetime | None = None, reason=None) -> TokenPair
```

- `session_id` is required and written as `sid` into both tokens.
- `refresh_cap` replaces `admin_refresh_exp` (required for impersonation): refresh and access `exp` are capped at it.
- `TokenPair` gains `refresh_jti: UUID` and `refresh_expires_at: datetime` so callers can persist the session.
- `verify(token, expected=None)` — unchanged behaviour apart from requiring `sid`.
- **New** `async def verify_active(self, token, expected=None) -> AnyClaims`:
  1. `claims = self.verify(token, expected)`.
  2. Load `storage.sessions.get(claims.sid)`; missing → `InvalidTokenError`; revoked or expired → `RevokedTokenError`.
  3. For impersonation, also load the parent session; if it is not active → `RevokedTokenError`.
  4. Return claims.

  `TokenService` therefore receives `storage` in its constructor (only `verify_active` uses it; add a test that `verify` still makes no storage calls).

### 5.5 Session lifecycle in the services

Introduce an internal helper (e.g. `tenantkit/sessions/service.py`, class `SessionService`, exposed as `kit.sessions`) that owns create / rotate / revoke so the auth services, access service and control plane do not duplicate logic.

**Transaction discipline (applies to every flow below and to §6).** Both existing adapters make an inner `transaction()` *join* an open outer one, so anything written inside a transaction is lost if that transaction rolls back. Therefore:

- Work whose writes must survive an error — provider authentication including `login_attempts.record_failure`, failure audit events, and the reuse-detection revoke — runs **outside** any transaction, and **after** any success-path transaction block has exited.
- Only the success path (state change + its success audit event) is wrapped, via the audit recorder (§6.4).
- `Storage` gains `def in_transaction(self) -> bool` (ContextVar-backed in all adapters). `audit.emit_standalone()` and the standalone revoke helper raise `RuntimeError` if `storage.in_transaction()` is true, so a misplaced failure write fails loudly in tests instead of silently rolling back.
- Required tests: lockout still trips after N failed logins through the new login flow; after a reuse-detection error propagates, the session is revoked and `token.reuse_detected` is persisted.

**Login** (admin and tenant):
1. Authenticate as today, **outside** any transaction (failures, lockout counting, and `auth.login.failed` / `auth.account.locked` events are written here, then the error is raised).
2. On success, open the audit recorder (one transaction):
   1. `sid = uuid4()`; `pair = tokens.issue_pair(..., session_id=sid)`.
   2. `sessions.create(Session(id=sid, kind=typ, subject_id=…, tenant_id=…, current_jti=pair.refresh_jti, expires_at=pair.refresh_expires_at))`.
   3. Audit `auth.login.succeeded`.

**Refresh** (admin, tenant, impersonation):
1. `claims = tokens.verify_refresh(token, expected=typ)` (signature, expiry, type).
2. `session = sessions.get(claims.sid)`; missing → `InvalidTokenError`; not active → `RevokedTokenError`.
3. Impersonation: parent session must be active, else revoke this session (`parent_revoked`) and raise `RevokedTokenError`.
4. Reload subject (and tenant); if inactive → revoke session (`subject_deactivated` / `tenant_deactivated`) and raise `InvalidTokenError` (same as today's error).
5. Issue new pair with the same `sid` (impersonation: `refresh_cap = parent.expires_at`; impersonation scope and role re-checked as today).
6. `rotated = sessions.rotate(sid, expected_jti=claims.jti, new_jti=pair.refresh_jti, expires_at=pair.refresh_expires_at, used_at=now)`.
7. Audit `auth.token.refreshed` (or `impersonation.refreshed`) in the same recorder transaction as step 6.
8. If `rotated is None` → **reuse detected**. Exit the recorder block first (signal the condition with a sentinel/return value, not by raising inside it), then — with no transaction open — `revoke(session_id=sid, cascade_children=True, reason="reuse_detected")`, `emit_standalone(token.reuse_detected, outcome="failure")`, and raise `RevokedTokenError`. The newly minted pair is discarded.

Steps 2–4 that revoke and raise (inactive subject/tenant, revoked parent) follow the same rule: the revoke happens outside any transaction before raising.

Sessions are sliding: each refresh extends `expires_at` by the type's `refresh_ttl` (capped for impersonation). Note: a client that fires two refreshes concurrently with the same token will trip reuse detection; document this in sub-doc 10 and the FastAPI guide ("serialise refresh calls client-side").

**Impersonation start** (`kit.access.impersonate`): the admin refresh token's `sid` becomes `parent_id`; the parent session must be active (else `RevokedTokenError`). Create the impersonation session, audit `impersonation.started`.

**Revocation operations** (all in a transaction with their audit event):

| API | Effect | Audit action |
| --- | --- | --- |
| `kit.admin_auth.logout(refresh_token=)` | verify signature (expired tokens → no-op return); `revoke(session_id=sid, cascade_children=True)`, reason `logout`. Idempotent; jti not checked. | `auth.logout` |
| `kit.tenant_auth.logout(refresh_token=)` | same for tenant sessions | `auth.logout` |
| `kit.access.end_impersonation(refresh_token=)` | revoke that impersonation session, reason `impersonation_ended` | `impersonation.ended` |
| `kit.admin_auth.logout_all(actor=)` | actor must be an admin access token; `revoke(kind="admin", subject_id=…, cascade_children=True)` (impersonation sessions are always children of an admin session), reason `logout_all` | `auth.logout_all` |
| `kit.tenant_auth.logout_all(actor=)` | actor must be a tenant access token; revoke `kind=tenant, subject_id` | `auth.logout_all` |
| `kit.control_plane.revoke_sessions(actor, subject_type: Literal["admin","tenant"], subject_id)` | permission `sessions:revoke`; `revoke(kind=subject_type, subject_id=…, cascade_children=True)`; reason `admin_revoked` | `session.revoked` |
| `kit.control_plane.list_sessions(actor, subject_type, subject_id, *, active_only=True, limit=50, offset=0)` | permission `sessions:read` | — (reads are not audited) |
| `change_password` (admin, tenant) | after updating the hash, `revoke(kind=…, subject_id=…, cascade_children=True)`, reason `password_changed` | `auth.password.changed` |
| `deactivate_admin` | `revoke(kind="admin", subject_id=…, cascade_children=True)`, reason `subject_deactivated` | `admin.deactivated` |
| `deactivate_tenant_user` | revoke the user's sessions, reason `subject_deactivated` | `tenant_user.deactivated` |
| `deactivate_tenant` | revoke `tenant_id=T` (covers tenant users **and** impersonation sessions into T), reason `tenant_deactivated` | `tenant.deactivated` |
| `kit.sessions.purge_expired(*, before=None)` | maintenance, no actor; `before` defaults to now | — |

Impersonation actors (`typ == "impersonation"`) are refused by `logout_all` and by every control-plane method (as today).

### 6.1 Domain model

```python
AuditOutcome = Literal["success", "failure"]
ActorType = Literal["admin", "tenant_user", "system", "anonymous"]

@dataclass(kw_only=True, frozen=True)
class AuditEvent:
    action: str                          # dotted name, see 6.2
    outcome: AuditOutcome
    actor_type: ActorType
    actor_id: UUID | None = None         # admin id / tenant user id; None for anonymous/system
    impersonator_id: UUID | None = None  # set when the actor is an impersonation token (act.sub)
    tenant_id: UUID | None = None        # tenant the action concerns, if any
    target_type: str | None = None       # "tenant" | "tenant_user" | "admin" | "session" | "account"
    target_id: UUID | None = None
    session_id: UUID | None = None
    token_jti: UUID | None = None
    reason: str | None = None            # impersonation reason / revoke reason
    metadata: Mapping[str, Any] = field(default_factory=dict)   # JSON-serialisable, never secrets
    id: UUID = field(default_factory=uuid4)
    occurred_at: datetime = field(default_factory=now)
```

Hard rule (security test): no event, in any field, ever contains a password, password hash, token string, or signing key. `metadata` for updates holds **changed field names** (and for role/scope grants, the new role names / scope mode), never values of `attributes` that could be sensitive.

### 6.2 Action catalogue

| Action | Outcome | Emitted by |
| --- | --- | --- |

| `auth.login.succeeded` | success | admin and tenant login |

### 6.3 Repository

```python
class AuditEventRepository(Protocol):
    async def append(self, event: AuditEvent, /) -> None: ...
    async def list(
        self, *, tenant_ids: Sequence[UUID] | None = None, actor_id: UUID | None = None,
        target_id: UUID | None = None, action: str | None = None,
        since: datetime | None = None, until: datetime | None = None,
        limit: int = 50, offset: int = 0,
    ) -> list[AuditEvent]: ...
    async def purge(self, *, before: datetime) -> int: ...
```

- `list` returns newest first (`occurred_at DESC, id DESC`). `tenant_ids=None` means no tenant filter; an empty sequence returns `[]`. `action` matches exactly or, if it ends with `.*`, by prefix (`tenant.*`).
- No `update` and no single-row delete. `purge` deletes rows with `occurred_at < before`.

### 6.4 Service and facade

- New `tenantkit/audit/service.py` → `AuditService`, exposed as `kit.audit`.
- `TenantKit(config=…, storage=…, providers=…, audit_hooks: Sequence[AuditHook] | None = None)` where
  `AuditHook = Callable[[AuditEvent], Awaitable[None]]` (export the alias).
- Internal API used by other services:
  - `async with audit.recorder() as rec:` opens `storage.transaction()`; `await rec.emit(event)` appends inside the transaction and queues the event. Hooks are dispatched only when the recorder that **opened the outermost storage transaction** exits successfully (i.e. after commit); on exception the queue is dropped. A nested recorder joins the outer recorder's queue. Entering a recorder while `storage.in_transaction()` is already true **without** an enclosing recorder raises `RuntimeError` — tenantkit operations must not be called inside a host-opened `storage.transaction()`, because hooks could fire before the host's commit (document this in sub-doc 11).
  - `await audit.emit_standalone(event)` — own transaction, then dispatch; raises `RuntimeError` if `storage.in_transaction()`. Used for failure events right before raising (see §5.5 transaction discipline).
- Hook dispatch: hooks run sequentially in registration order, each awaited; exceptions are caught and logged via `logging.getLogger("tenantkit.audit")` at `ERROR` with the event id and action (never the event's metadata). Hooks are never invoked for rolled-back events.
- Public API:
  - `await kit.audit.list(actor, *, tenant_id=None, actor_id=None, target_id=None, action=None, since=None, until=None, limit=50, offset=0) -> list[AuditEvent]` — admin access token with `audit:read`. **Visibility**: actor perms include `*` or the admin's impersonation scope mode is `all` → everything; scope `list` → only events whose `tenant_id` is in the scope list (platform-level events with `tenant_id=None` are hidden); scope `none` without `*` → `PermissionDeniedError`. A requested `tenant_id` outside the visible set → `PermissionDeniedError`. `limit` is clamped to 1–500.
  - `await kit.audit.purge(actor, *, before: datetime) -> int` — admin with `audit:purge`; the `audit.purged` event is written **after** the purge in the same transaction so it survives.

Existing services must be refactored so each state change and its audit event share one transaction (today they mostly call repositories directly without `storage.transaction()`; wrap them).

### 7.2 Host integration

```python
from pymongo import AsyncMongoClient
from beanie import init_beanie
from tenantkit.storage.beanie import BeanieStorage, document_models

client = AsyncMongoClient(MONGO_URL, uuidRepresentation="standard", tz_aware=True)
db = client["app"]

tk_models = document_models(prefix="mt_")                 # once per process
await init_beanie(database=db, document_models=[*app_models, *tk_models.all])

storage = BeanieStorage(database=db, models=tk_models)    # transactions=True by default
kit = await TenantKit.create(config=config, storage=storage)
```

- `document_models(prefix: str = "mt_") -> BeanieModels`: builds (dynamically, with `Settings.name = prefix + "<collection>"`) and caches the Document classes. Calling again with the same prefix returns the same object; calling with a different prefix in the same process raises `ConfigError` (D11). `BeanieModels` is a frozen dataclass with one attribute per collection plus `all: tuple[type[Document], ...]`.
- Prefix validation: same rules as the SQL table prefix.
- `BeanieStorage(*, database, models, transactions: bool = True)`; never creates a client or calls `init_beanie`. With `transactions=False` emit a `logging` WARNING once at construction stating that multi-step operations are not atomic and that audit writes are no longer fail-closed (a change can persist without its audit event).

### 7.4 Adapter rules

- **Mapping:** Documents never leave the adapter; repositories return the existing domain dataclasses (and `LoginPolicy` is re-validated exactly as the SQLAlchemy adapter does).
- **UUIDs and datetimes:** `health_check()` raises `ConfigError` if `database.codec_options.uuid_representation` is not `STANDARD`. Datetimes are returned timezone-aware UTC regardless of the client's `tz_aware` setting.
- **Transactions:** `transaction()` uses a per-instance `ContextVar` holding the active `AsyncClientSession` (mirror the SQLAlchemy adapter's nesting semantics: inner calls join the outer transaction). Every repository operation passes `session=` when one is active. On `transactions=False`, `transaction()` is a no-op context manager.
- **`health_check()`:** `ping`; confirm the Document classes from `models` are initialised against this `database`; when `transactions=True`, run `hello` and require `setName` (replica set) or `msg == "isdbgrid"` (mongos), else `StorageUnavailableError`.
- **Uniqueness and errors:** `DuplicateKeyError` → `AlreadyExistsError`; other `PyMongoError` → `StorageError` (original chained, message without connection strings). `TenantUser.create` checks the tenant exists inside the transaction (no foreign keys in Mongo) → same error as other adapters.
- **Atomic lockout:** `record_failure` must be a **single** server-side `find_one_and_update` with `upsert=True`, `return_document=AFTER`, using an aggregation-pipeline update that increments `failed_count`, preserves an existing future `locked_until`, and sets `locked_until` when the new count reaches `max_attempts` — satisfying the existing `test_concurrent_failures_lock_atomically` contract test.
- **Session rotate:** `find_one_and_update({"_id": sid, "revoked_at": None, "current_jti": expected}, {"$set": …}, return_document=AFTER)`.
- **Session revoke / audit purge / purge_expired:** `update_many` / `delete_many`.
- **No hard deletes** other than `audit.purge` and `sessions.purge_expired` (same as SQL).

## 10. Test cases (in addition to contract tests)

Sessions and revocation:
- Login creates exactly one active session; both tokens carry its `sid`; refresh `jti == current_jti`.
- Refresh rotates `current_jti`, extends `expires_at`, keeps `sid`.
- Re-using the previous refresh token → `RevokedTokenError`, session and child impersonation sessions revoked with `reuse_detected`, `token.reuse_detected` audited; the legitimately rotated token now also fails.
- Logout makes refresh fail with `RevokedTokenError`; logout is idempotent and a no-op for an expired token.
- `logout_all` for an admin also kills their impersonation sessions; impersonation actor is refused.
- `revoke_sessions` requires `sessions:revoke`; `list_sessions` requires `sessions:read`.
- Deactivating a tenant revokes its users' sessions and impersonation sessions into it, not other tenants'.
- Deactivating a user/admin and changing a password revoke all their sessions.
- Revoking the admin parent session makes impersonation refresh and `verify_active` fail.
- Impersonation session `expires_at` never exceeds the parent session's.
- `verify` still accepts an access token of a revoked session until expiry (documented behaviour) and makes no storage calls; `verify_active` rejects it.
- 0.1-style tokens (no `sid`) are rejected by `verify` and `refresh`.

Audit:
- Every action in §6.2 is emitted once with the documented fields (table-driven test).
- A failing `audit_events.append` rolls back the corresponding change (e.g. tenant not created) and the error propagates.
- Failure events (`auth.login.failed`, `auth.account.locked`, `token.reuse_detected`, `impersonation.denied`) persist even though the operation raises.
- Hooks receive committed events only, in order; a raising hook is logged and the operation still succeeds; no hook call on rollback.
- `include_failed_login_email` off → no email anywhere in the event; on → email in metadata.
- Security: serialise every emitted event in the test run and assert no password, hash, token string, or key appears.
- `audit.list` visibility: `*` sees all; scope `list` sees only its tenants and not platform events; scope `none` denied; out-of-scope `tenant_id` filter denied; impersonation and tenant actors denied.
- `audit.purge` deletes older events and leaves its own `audit.purged` event.

Beanie:
- Full `StorageContract` passes on a replica set.
- `health_check` fails with `StorageUnavailableError` on a standalone server when `transactions=True` (can be unit-tested by faking the `hello` reply) and with `ConfigError` on non-standard UUID representation.
- `document_models` caching and different-prefix `ConfigError`.
- Returned datetimes are tz-aware UTC.

## 11. Acceptance criteria

1. A tenant user can log in, refresh, and log out; after logout the refresh token is rejected and `verify_active` rejects the access token, while `verify` accepts it until it expires.
2. Re-presenting a rotated refresh token revokes the session and is visible in the audit log as `token.reuse_detected`.
3. An admin with `sessions:revoke` can revoke another subject's sessions; deactivating a tenant, user, or admin and changing a password revoke the affected sessions.
4. Ending or losing the admin session ends any impersonation started from it.
5. Every action in §6.2 lands in the audit store inside the same transaction as the change; audit hooks observe committed events only and cannot break operations.
6. An admin with `audit:read` can list events within their visibility; `audit:purge` removes old events.
7. `pip install tenantkit[mongo]` plus the documented `init_beanie` setup gives a working `BeanieStorage` that passes the full contract suite and the end-to-end flow against a MongoDB replica set in CI.
8. SQLAlchemy and in-memory adapters pass the extended contract; Alembic autogenerate picks up the two new tables with the configured prefix.
9. Docs `10`–`12` exist, `00/02/07/08`, README, and the FastAPI example are updated and consistent; version is `0.2.0` with a changelog listing the breaking changes.
10. CI is green: ruff, mypy strict, ≥ 90 % coverage, SQLite + PostgreSQL + MongoDB.
